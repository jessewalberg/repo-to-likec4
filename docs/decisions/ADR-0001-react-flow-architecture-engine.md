## Decision

Rebuild the repo→architecture skill as a **custom React + React Flow (`@xyflow/react` v12, MIT)** application driven by a **schema-validated, agent-owned `architecture.json` manifest**, replacing all diagram-as-code engines (LikeC4, Mermaid, Excalidraw, C4 tooling). The renderer is a projection of the manifest; an AI agent **patches** the manifest incrementally (RFC 6902 / `fast-json-patch`) instead of regenerating, and a per-field machine-vs-human **provenance** model + a **`suppressions`** list let human edits survive agent re-runs. Ship as a self-contained `viewer.html` with an inlined JSON data island plus the committed manifest, generated by a 5-stage decomposed agent pipeline (recon → model → layout → view-refine → validate). Layout via `elkjs`, **run once then frozen** (pinned nodes are fixed input; no automatic full re-layout).

## Context

The skill has pivoted twice (LikeC4 → Mermaid, both 2026-05-29). Diagram-as-code engines regenerate from scratch each run (losing manual edits), have weak/ugly auto-layout, carry DSL gotchas, and don't produce a beautiful, *learnable* page for understanding unfamiliar / vibe-coded codebases. The new goal: a beautiful, interactive, **in-place-editable** architecture page an agent can generate *and* keep current. A 24-agent research sweep found the rendering choice (React Flow) is convergent and low-risk; the genuine risk is the incremental-update merge layer and the cost of "beauty on a blank canvas."

## Options considered

1. **React Flow + agent-owned JSON manifest** *(chosen)* — declarative controlled state is the best fit for agent-patchable, human-editable source-of-truth.
2. **AntV X6** — ships editing chrome (undo/redo/snapping/clipboard/history) for free, but its imperative `fromJSON` round-trip fights the JSON-Patch merge model and its in-memory history competes with the manifest. *Runner-up; 1-day Phase-0 spike recommended.*
3. **AntV G6 5.x / Cytoscape.js / Reagraph (WebGL)** — win only at >1,000 simultaneously-visible nodes (not expected after lane-collapse). Scale escape-hatch, not the base.
4. **Keep a diagram-as-code engine (LikeC4/Mermaid/D2+TALA) + a JSON position manifest** — the strongest "what-would-change-our-mind" alternative: it also achieves in-place persistence and is beautiful-by-default, for far less bespoke engineering. Rejected *unless* the Phase-0 merge spike fails or design capacity is absent.
5. **tldraw SDK** — ruled out ($6,000/yr commercial license; OSS non-starter).

## Chosen approach

See the research report for the full data model, extraction stack, layout policy, merge algorithm, packaging, pipeline, and phased plan. Headline commitments: stable `<kind>:<canonical-path>` node IDs + `idAliases`; positions stored **per-view**; explicit node `width`/`height` (ELK can't measure); `@xyflow/react/dist/base.css` with owned `--xy-*` tokens; OKLCH dark-first design system; `codegraph` MCP for on-demand call-graph drill-down.

## Tradeoffs

Gain: true in-place editing, full control of beauty + click-through, no DSL, new diagram families (state/ER/flowchart) become buildable, OSS/offline delivery. Cost: we now own rendering, layout orchestration, the merge layer, and the entire visual design — none of which existed as concerns with a DSL engine. "Beautiful" is no longer free.

## Risks

Incremental merge / stable-ID churn is the likeliest failure (and is net-new prior art); semantic drift without `suppressions`; ELK batch-vs-incremental tension (managed decay); multi-week design cost; `file://` fetch; DOM/SVG scale ceiling; unmeasured per-run token cost; fast-moving competitors (DeepWiki, EraserBot, Google Code Wiki). Dependency traps: use `@dagrejs/dagre` (not legacy), `fast-json-patch` (not `rfc6902`), pin `html-to-image@1.11.11`; `trimerge` + Stack Graphs are abandoned/archived.

## What would change our mind

- Phase-0 spike shows the three-way merge can't preserve human edits across realistic refactor churn → revert to a DSL engine + JSON position manifest.
- Repos routinely exceed ~1,000 visible nodes after collapse → switch renderer to Cytoscape/G6.
- A competitor ships true edit-surviving in-place patching → moat narrows to distribution; re-weight.
- No design/frontend capacity for a genuinely beautiful canvas → a beautiful-by-default constrained engine (D2+TALA / Mermaid `architecture-beta`) becomes pragmatic.
- Undo/redo/snapping/clipboard/history become hard requirements with no appetite to build them → AntV X6.

## Scope addition (2026-05-29) — it's a docs app with a sidebar, not just a canvas

Maintainer-directed: the viewer is a **documentation application** with a navigation **sidebar** (Documentation, Architecture, nested Modules docs, Learning), supporting all three candidate layouts at once via one free-form nav tree + per-node `doc`/`lesson` attachments. Adds **global ⌘K search** and a **Changelog** ("what changed between commits"). Docs are authored by the **same decomposed agents** (View-Refine stage), human-editable with provenance. The proven merge engine extends unchanged to doc pages + nav entries; the changelog is produced by the existing `MergeReport`. New artifacts: `site.json` (nav), `pages/**.md` (editable docs), `changelog.json` (feed). Reinforces the shadcn / React-Flow-UI-Components choice (the `Sidebar` primitive shares the canvas's design system). Full spec: [app-shell-and-ia](../design/app-shell-and-ia.md). Phase-1 absorbs the app shell + search; changelog lands in Phase-2.

## Phase-0 outcome (2026-05-29) — gating spike PASSED

The de-risking spike ([phase0-findings](../research/phase0-findings.md)) confirmed the decision; nothing flipped it.
- **Three-way merge: proven.** 8/8 tests, including a **real** software-factory file-move + module-split with correct rename detection — human edits (label/pin/annotation/position) survived real ID churn, suppression held. The merge is the load-bearing risk and it works.
- **elkjs: viable — layout policy reworded.** No native pin survives orthogonal routing, so the freeze is **app-owned**: the manifest is truth, ELK is a *candidate generator*, new nodes are seeded with `elk.position` hints and an **overlap guard** resolves collisions. (Supersedes "ELK fixed-position pinning" below.)
- **AntV X6: evaluated and dropped.** `fromJSON` is a zero-merge whole-graph replace (wipes human edits); history keys on cell paths, not the manifest. Stay on React Flow; get undo/redo from `zundo` + RF snapping.
- **Token cost / trigger: resolved.** Incremental runs ~$0.05–0.16/push. **Default = manual `/map`; opt-in = CI-on-merge with incremental + Batch + Haiku-view-refine + debounce + daily spend cap.** Tiering: deterministic stages $0, Model Builder = Sonnet 4.6, View-Refine = Haiku 4.5.

## Maintainer decisions (2026-05-29)

- **Phase-0 spike: approved — proceed now**, including the 1-day AntV X6 touch and a token-cost benchmark.
- **Update trigger: deferred** — choose manual vs CI vs hook *after* the Phase-0 token-cost benchmark; let the economics decide.
- **Visual direction: LIGHT, not dark.** Overrides the research's dark-mode-first recommendation. Keep the OKLCH token approach + 5-hue semantic palette, but retune for a near-white canvas; elevation via hairline borders + soft shadows rather than luminance-on-dark. Phase-1 build starts from **React Flow UI Components** (shadcn-based) as a head-start, then customizes. Maintain WCAG contrast on light.
