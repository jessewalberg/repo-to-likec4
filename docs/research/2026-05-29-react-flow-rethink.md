# Rethink: a custom React + React Flow architecture-docs system

**Date:** 2026-05-29
**Status:** research synthesis (informs [ADR-0001](../decisions/ADR-0001-react-flow-architecture-engine.md))
**Method:** 24-agent dynamic research workflow (`repo-arch-rethink-research`, run `wf_28fd8e4c-6c6`) — 11 parallel research briefs, each adversarially critiqued + fact-checked, then synthesized and red-teamed. 1.36M agent tokens, 589 tool calls.

---

## Bottom line

> Build it on **React Flow (`@xyflow/react` v12, MIT)** — the convergent verdict across all 11 dimensions — but treat the renderer as the easy 20%. The hard, defensible **80% is the schema-validated JSON manifest, a layout-once-then-freeze model, and explicit machine-vs-human field provenance (including semantic suppression)** that lets an agent patch the graph forever without clobbering human edits. Ship it as a self-contained, JS-inlined HTML page plus a committed `architecture.json` data island, generated by a 5-stage decomposed agent pipeline (recon → model → layout → view-refine → validate). ~70% of the old LikeC4 skill's *thinking* survives (recon philosophy, manifest, archetypes, 6-property clickable node, anti-hairball lanes, per-language extraction, phased generation); 100% of the LikeC4 DSL surface is dropped.
>
> Two things to budget for that the briefs underweight: **"beauty on a blank canvas" is a real multi-week frontend project** (React Flow gives nothing for free that LikeC4 gave automatically), and **the incremental-update merge layer — not the renderer — is where this product lives or dies.**

**Final red-team call: GO-WITH-CHANGES.** The renderer choice is correct and the version facts check out. But: make the Phase-0 spike prove stable-ID merge against *two real refactor commits* (not a fake recon); add suppression/alias garbage-collection to the schema before locking it; benchmark token cost on the testbed before committing to any per-push trigger; do the 1-day X6 spike so "skip it" is evidence-based.

## The rendering verdict

| | Pick | Why |
|---|---|---|
| **Recommended** | **React Flow `@xyflow/react` v12.10.2 (MIT)** as a custom-node/custom-edge renderer over an agent-owned JSON manifest. Import `@xyflow/react/dist/base.css` (not `style.css`) and own every `--xy-*` token. | The #1 hard requirement — "update in place, never regenerate, survive human edits" — maps 1:1 onto RF's controlled-state model: every node/edge is plain serializable JSON (`toObject()` → `{nodes, edges, viewport}`), every gesture emits a typed `NodeChange` delta, and `updateNode`/`updateNodeData`/`addNodes`/`deleteElements` give surgical patches. Custom nodes are just React components — the only way to hit "designed, not slop" with full control of the click-through panel + source links. The agent ecosystem is real (xyflow ships `/llms-full.txt` for agents). **Confidence: high.** |
| **Runner-up** | **AntV X6 v3.x (MIT)** — the AntV family's dedicated *diagram editor* (not G6, the analytics renderer), with Cytoscape.js (canvas/WebGL) as the scale escape-hatch. | X6 ships undo/redo + snapping + clipboard + history for free, which RF makes you self-build (RF gates undo/redo as a *Pro example*). |
| **When the runner-up wins** | X6 only if, after a spike, hand-building editing chrome proves unaffordable AND those become hard requirements. Cytoscape only if a repo routinely needs **>1,000 simultaneously-visible nodes** after grouping/collapse (i.e. the "collapse to lanes" strategy fails). Neither is expected for architecture maps. | |

**Five of the strongest dimensions independently land on React Flow.** The pushback (X6 omission, Cytoscape scale) attacks completeness, not the core choice. The red-team's sharper framing of *why*: **you must build the provenance-aware three-way merge layer regardless of renderer** — X6's `fromJSON()` is an imperative whole-graph load, no more mergeable than RF — so the tiebreaker is which renderer fights agent-owned-JSON-as-source-of-truth *least*, and that's React Flow's declarative controlled state. X6's built-in history is actually a *liability* here: an in-memory imperative command stack competes with your manifest-as-source-of-truth instead of feeding a git-diffable JSON-Patch log.

### Ruled out
`tldraw` SDK ($6,000/yr commercial license — non-starter for an OSS skill), `vis-network` (order-of-magnitude slower), `d3-graphviz` (static SVG, not editable), raw D3 (too low-level for agent generation), Nivo/ECharts (not graph editors), `react-digraph`/`Reaflow` (unmaintained / strictly worse than RF). `AntV G6 5.x` is a credible beauty/scale challenger but is an *analytics* renderer with a weaker structured-patch editability story and a React strict-mode double-init footgun.

## The proposed system — "Cartograph" (working name; `/map` skill)

> An Agent Skill that turns any repo — especially sprawling, vibe-coded ones — into a beautiful, clickable, **in-place-editable** React Flow architecture page you can learn a codebase from in one session, backed by a schema-validated JSON manifest the agent **patches instead of regenerating**.

### Data model — one committed file, `docs/architecture/architecture.json`

A **fused model+layout document** with explicit field provenance. Nodes are a **map keyed by stable ID** (not an array) so independent adds/removes never positionally collide on three-way merge. **Positions live per-view, not on the node** (a node in Context and Container views has two positions; storing on the node makes views fight).

```jsonc
{
  "schemaVersion": 2,
  "meta": { "repo": "org/name", "archetype": ["web-app","stateful-domain"], "reconCommit": "<sha>" },
  "nodes": {
    "service:apps/api": {
      "id": "service:apps/api",            // STABLE: '<kind>:<canonical-module-path>'; rename tracked via idAliases
      "type": "service|webapp|worker|datastore|cache|queue|external|function|gateway|person|state|entity|decision",
      "parentId": "lane:backend|null",     // ROOT-level — subflow group membership
      "data": {
        "label": "API",                    // human-editable
        "summary": "REST API for the web client",  // node face; LLM-owned, human-editable
        "description": "…markdown…",        // click panel; LLM-owned, human-editable
        "technology": "Node/Express",
        "icon": "simple-icons:nodedotjs",   // own icon registry; never a wrong-meaning glyph
        "links": [{"label":"Source","url":"https://github.com/org/name/blob/<sha>/apps/api/src/index.ts#L1-L40"}],
        "metadata": { "path":"apps/api/src/index.ts", "language":"ts", "loc":420, "owner":"@team" }, // recon-OWNED
        "provenance": { "label":"machine", "summary":"human", "position":"human" }, // per-field — THE merge contract
        "pinned": true,                     // human dragged it → layout pass skips its position forever
        "confidence": "static|inferred|unknown"
      },
      "width": 200, "height": 88           // EXPLICIT dims (ELK/Dagre can't measure on server)
    }
  },
  "edges": {
    "e:service:apps/api->datastore:db": { "id":"…","source":"service:apps/api","target":"datastore:db",
      "type":"sync|async|reads|writes|emits|listens|imports|usesType","animated":false,"label":"persists orders",
      "data":{ "confidence":"static", "provenance":{"label":"machine"} } }
  },
  "suppressions": { "edges": ["e:service:apps/api->cache:redis"], "nodes": ["file:apps/api/src/util/log.ts"] },
  "idAliases": { "service:apps/old-api": "service:apps/api" },
  "groups": { "lane:backend": { "id":"lane:backend","label":"Backend","laneType":"layer|column|radial-hub","color":"emerald" } },
  "views": [ { "id":"context","title":"System Context","level":1,"nodeIds":[],"layoutDir":"LR",
               "layout": { "service:apps/api": {"x":120,"y":40} } } ]
}
```

Two fields close the deepest gaps the critiques found:
- **`suppressions`** — a "hide this node/edge, never show again" gesture that **recon must honor on every re-run**. Without it, the agent re-adds structural edges the human deliberately removed, and the design fails *before persistence matters*. This is the single best idea in the design.
- **`provenance`** (per-field `machine|human`) — the formal contract that makes the three-way merge safe.

Committed under `docs/architecture/` so diffs are reviewable in PRs — the in-place story made concrete.

### Extraction stack — three tiers, language-agnostic core + per-language enhancers

| Tier | What | Tools |
|---|---|---|
| **1 — cheap boundary recon** (<10s, any repo) | node inventory + boundary edges | `universal-ctags --output-format=json` + `ast-grep` YAML rules. **For JS/TS, prefer Knip or OXC `oxc_resolver`** (correct module resolution incl. barrel files / framework wiring that ctags+ast-grep miss — the repo-extraction critique's strongest point). |
| **2 — per-language module graph** | precise `imports`/`calls`/`usesType` edges | `dependency-cruiser` (`--cache`, git-metadata) + `ts-morph` (JS/TS); `grimp` (Python); `go list -json` + `x/tools/callgraph` (Go); `jdeps` (Java). |
| **3 — symbol/call graph** (on-demand only) | drill-into-a-node detail | query the **existing tree-sitter `codegraph` MCP** via `callers`/`callees`/`trace` — never pre-render the full call graph. |

- **Incremental invalidation:** XXH3 content hash per file (or `git diff --name-status`); delete + re-extract only changed files.
- **Hairball pre-pass:** deterministic **Louvain community detection with a fixed seed** (derived from repo root commit) for stable groupings → seeds lane/group assignments.
- **Avoid** CodeQL (needs a full build, minutes, security-query overkill) and SCIP as the *primary* driver (needs the repo to compile; many vibe-coded repos don't). Both are optional high-precision overlays only. **Stack Graphs is archived (Sep 2025) — do not depend on it.**

### Layout engine — `elkjs`, run once then frozen

`elkjs` (the maintained Eclipse Layout Kernel JS port — **GWT-compiled JavaScript ~600KB gzipped, NOT WASM**; three briefs got this wrong, the red-team confirmed the correction). Config: `algorithm=layered, edgeRouting=ORTHOGONAL, hierarchyHandling=INCLUDE_CHILDREN, thoroughness=5`. Run server-side at generation time (worker when invoked).

**Decisive policy (resolving the sharpest cross-brief conflict — ELK is a *batch* engine that reshuffles everything):** layout runs **once** to seed a view; positions persist per-view; **ELK is never re-run on the full graph automatically.** New nodes get positions via ELK **Fixed Layout / `noLayout`** (existing/pinned nodes fixed as input, only new nodes placed). Full re-layout happens only on explicit user "auto-arrange" of unpinned nodes. This is how manual tweaks survive — the renderer never calls `setNodes` with a fresh ELK array.

> ⚠️ Red-team caveat: "freeze" isn't a clean win — it's *managed decay*. Pinning 90% of the graph and dropping new nodes into gaps will produce some overlaps/crossings over time that the overlap validator flags with no recourse but a full re-layout the freeze forbids. "Beautiful" and "never re-layout" are in tension on every incremental run. `dagre` → use the maintained **`@dagrejs/dagre`** scoped fork only, never the abandoned legacy `dagre`, and only for simple single-root tree subviews.

### Update-in-place model — provenance-driven three-way merge

The manifest is the source of truth; the renderer is a projection. On every agent re-run: **base** = last committed manifest, **left** = fresh recon, **right** = current manifest (with human edits). Merge per stable-ID key (the map representation makes this conflict-free for independent keys):

1. **recon-owned fields** (path, links, metadata, structural edges) — left wins, refreshed every run.
2. **human-owned fields** (`position`, `pinned`, manually-edited `label`/`summary` where `provenance=='human'`) — right always wins; agent never overwrites.
3. **new structural nodes/edges** — added, *unless* their id is in `suppressions`.
4. **removed-in-left nodes** — NOT hard-deleted; flagged `confidence='unknown'` + visually muted; human confirms.
5. **renames** — detected by edge-neighborhood similarity, recorded in `idAliases` so old-id layout/edits migrate.

Patches are **RFC 6902 JSON Patch** via **`fast-json-patch`** (the dominant lib — not the minority `rfc6902`), auditable/reversible/git-diffable. The agent **never passes the whole manifest into a context window** — it computes the delta from the recon diff and emits targeted ops.

### Packaging — self-contained HTML + inlined JSON island

Skill **maintainer** builds a single viewer HTML (private Vite workspace + `vite-plugin-singlefile`; React 19 + `@xyflow/react` + elkjs-in-worker inlined, ~600–900KB raw). The skill scaffolds **two committed files** into the target repo: `viewer.html` (versioned by the skill, replaced on schema bumps) and the data.

**Critical fix:** the data is embedded as an inline `<script id="arch-data" type="application/json">…</script>` **island inside `viewer.html`**, NOT fetched at runtime — because `fetch()` of a sibling JSON file **fails under `file://`** (browser SOP), which would break offline viewing. The agent edits the JSON island in place; the human gets clean git diffs; both offline (`file://`) and GitHub Pages (no CSP header — verified) work. **Zero Node dependency in the user's repo at update time** — the agent regenerates the island, never runs a build.

### Generation pipeline — 5 decomposed stages

0. **Setup** — detect languages, compute blob-URL base.
1. **Recon Agent** — deterministic Tier-1/2 extraction → manifest model + Louvain groups + archetype classification; **pauses for human review** if the repo is unfamiliar (kept from old skill).
2. **Model Builder** — recon facts → typed nodes/edges, stable IDs, source links, 6-property `data`; positions null.
3. **Layout Agent** — `elkjs` in Node/worker with the fixed-layout/pinned policy; writes per-view positions.
4. **View-Refine Agents** (parallel, one per view) — LLM writes `summary`/`description`/labels per view using **schema-constrained structured outputs** (`additionalProperties:false`); generate **per-view in smaller chunks (not one 300-node blob)** and cross-validate IDs to avoid hallucinated edges.
5. **Assembler + Validator** — deterministic checks (no orphan edges; every node source-linked; no bbox overlap; flows leaf-level); failures trigger targeted regen of only the violating subgraph; emit final manifest + screenshot self-check.

Incremental re-run skips stage 4 for unchanged views and runs the provenance merge.

## UX / design direction

### Visual system (anti-AI-slop = constraint, not freedom)
> **⚠️ Maintainer override (2026-05-29): LIGHT design, not dark.** The research below recommended dark-mode-first; the maintainer chose a **light** design. Keep the OKLCH token method + 5-hue semantic palette but retune for a near-white canvas (elevation via hairline borders + soft shadows, not luminance-on-dark); maintain WCAG contrast. Phase-1 starts from React Flow UI Components (shadcn) then customizes. The dark-first spec below is preserved as the research record.

Dark-mode-first. Near-black canvas `#0D0D10` (not pure `#000` — OLED bloom). **Elevation via luminance steps, not shadows** (L0 canvas → L1 node `rgba(255,255,255,0.04)` → L2 hover `0.07` → L3 panel). **5-hue semantic node palette + one 10-step neutral ramp, generated in OKLCH:** service=emerald, frontend=cyan, datastore=violet, infra=amber, external=slate, queue/event=rose. Token tiers primitive→semantic→component. **Node card anatomy:** 8px type-colored header stripe + 24px icon (`@icons-pack/react-simple-icons`+devicons; fall back to official SVG URL or no icon — never a wrong-meaning glyph) + 14px label (Geist/Inter, -0.02em) + mono tech badge + truncated summary + source link; 6–8px radius (never `rounded-2xl`), 1px type-colored border at 0.4 alpha. **Three named edge variants only:** orthogonal solid (sync), bézier solid colored-by-target (data-flow), dashed animated rose (async — respects `prefers-reduced-motion`). **Accessibility from day one:** node type never encoded by color alone (icon + shape cue, WCAG 1.4.1); keyboard traversal + visible focus rings.

### Interaction model — Shneiderman spine (overview → zoom/filter → details), 3 modes
- **Landing:** all lanes/groups visible but **collapsed to boundary nodes**, internal edges hidden — keeps visible node count in the low hundreds (the primary scale lever; RF is DOM/SVG and degrades past a few hundred complex nodes).
- **Explore:** click a group to expand; **semantic-zoom LOD** swaps full node bodies for lightweight placeholder divs below ~0.5 zoom (hand-built `useStore`-zoom pattern, debounced).
- **Focus:** click a node → focus+context (neighborhood highlighted, rest dimmed) + right-side panel: markdown description, human-readable in/out edge sentences ("Called by X, writes to Z"), source deep-links, alphabetized metadata, an "Explain this" button.
- **C4 altitude ladder** = separate view objects over one shared node pool (Context ≤9 / Container ≤15 / Component ≤15) with `onNodeClick` drill-down; positions stored per-view.
- The four families LikeC4 **couldn't** draw (state machines, ER, branching flowcharts, class) become **first-class custom node/edge types** — a documented weakness turned into new capability. (Budget real effort for sequence/swimlane: RF has no native lifeline layout.)

### Learning journey
Agent auto-authors a 3–5 step **guided tour** (stored as a `tours` array of `{nodeId, prose, highlightEdgeIds}`): what is this repo → the main lanes → the primary entry point → the most-changed hotspot (from git churn) → the external boundary. Three role-based entry buttons: **Fix a bug** → hotspot; **Add a feature** → entry point; **Understand the system** → overview. Tour steps carry source anchors and self-flag as stale (Swimm pattern) when their node id is suppressed/removed. **Uncertain edges/nodes (`confidence=inferred|unknown`) render visually distinct** so a newcomer trusts the certain structure and treats inferences as hypotheses — the diagram signals its own confidence rather than bluffing.

**Reference inspirations:** DeepWiki (node→prose→source click chain; our edge = in-place editability), IcePanel (beauty + multi-level C4 nav — the bar to clear), Linear (OKLCH 3-var dark theme), Vercel Geist (premium-via-constraint: narrow palette, 8px grid, low-alpha borders), Sourcetrail (3-panel focus+context). **Negative example:** the React Flow "Turbo Flow" purple→blue edge gradient is the exact AI-slop tell to avoid. **Closest live competitor:** EraserBot (CI agent that regenerates+commits diagrams) — our moat is true in-place patch semantics + local/offline OSS delivery, not "agent keeps it current."

## Open questions for the maintainer

1. **Trigger model** for incremental updates: manual `/map` re-run, git pre-commit hook, or CI on push? Sets the latency budget + whether elkjs needs guaranteed worker offload. *(Workflow's lean: manual + optional CI, not pre-commit.)*
2. **Private-repo / public-Pages leak:** `architecture.json` embeds file paths + symbol names. Refuse Pages deploy when repo visibility ≠ Pages visibility, or offer a redaction mode?
3. **Beauty bandwidth:** "designed, not slop" on RF's blank canvas is a multi-week frontend project, not a styling checklist. Is there design/frontend capacity, or should Phase 1 lean on **React Flow UI Components** (shadcn-based) as a head start?
4. **Scope of new diagram families (Phase 4):** state-machine/ER/class are achievable; sequence/swimlane needs custom layout with no native RF support. Sequence essential for v1-full or deferrable?
5. **Stable-ID rename detection error bar:** false rename-merge silently moves a human's layout to the wrong node; false miss orphans edits. Acceptable error rate?
6. **X6 spike:** worth a 1-day Phase-0 touch to confirm we aren't under-valuing its built-in undo/redo+snapping+history?
7. **Multi-repo / monorepo story:** one manifest+page per service, or a landscape page linking sub-pages? Affects schema (cross-page refs) + chunk-by-seam logic.
8. **Token cost of an incremental run** — unbenchmarked, and the decisive economic question for a skill that may run on every push.

## What would change our mind

- If a Phase-0 spike shows the provenance three-way merge **cannot reliably preserve human edits across realistic recon churn** (ID instability on common refactors), the whole "custom canvas beats diagram-as-code" thesis weakens — a Mermaid/LikeC4 engine + a JSON position manifest would deliver the same in-place value for far less bespoke engineering.
- If target repos routinely exceed **~1,000 visible nodes even after lane-collapse**, RF's DOM/SVG ceiling bites → Cytoscape.js / G6 becomes the renderer (flips the verdict on scale).
- If **EraserBot/DeepWiki ship true in-place patch semantics** that survive manual edits, the moat collapses to "local/open-source/offline delivery" alone — real, but a distribution advantage, not a product one.
- If a design audit finds **no capacity to build a genuinely beautiful** node/panel/edge system, a beautiful-by-default constrained engine (D2 + TALA, or Mermaid `architecture-beta`) becomes pragmatic despite weaker editability.
- If **undo/redo + snapping + clipboard + history become hard requirements** with no appetite to hand-build, AntV X6 wins the renderer slot.
- If schema-constrained array generation **reliably hallucinates cross-references** at the node counts we need even with chunking, move to smaller per-subgraph generations with heavier deterministic stitching.

## Top risks (mitigations in the data model + plan)

1. **Incremental merge is the product, and it's unsolved prior art.** ID churn on rename/refactor orphans every human edit — the likeliest real-world failure. → stable path-derived IDs + idAliases + Phase-0 spike *first*.
2. **Semantic drift beyond position** — agent re-adds deliberately-removed edges. → `suppressions` is a first-class, recon-honored field, not optional.
3. **Beauty is not free** — RF gives unstyled primitives; every node face/panel/edge/legend/theme is hand-built. → constraint-driven design system locked in Phase 1; consider RF UI Components.
4. **ELK is a batch engine** fighting edit-in-place. → layout-once-then-freeze + pinned fixed-input + per-view positions + no automatic full re-layout.
5. **v12 measured-dimensions footgun** — ELK can't measure; v12 stores `node.measured` separately. → explicit fixed dims in manifest + CSS-clamped fixed-height node bodies.
6. **`file://` fetch breaks offline.** → inline the data as a `<script type=application/json>` island.
7. **Scale/DOM ceiling** — complex nodes jank in the low hundreds (not the optimistic "10k"). → collapse-to-lanes default, semantic-zoom LOD, canvas minimap; Cytoscape escape-hatch.
8. **Dependency traps:** `@dagrejs/dagre` not legacy `dagre`; `fast-json-patch` not `rfc6902`; pin `html-to-image@1.11.11`; Stack Graphs archived (don't depend); `trimerge` abandoned (implement the map-merge directly).
9. **Tier-1 extraction unreliable on modern JS/TS** (barrel files, Next routing, NestJS DI, FastAPI deps). → prefer Knip/OXC resolver as JS/TS Tier-1; carry `confidence='inferred'` for pattern-matched edges.
10. **Competitive window** — DeepWiki / Google Code Wiki / EraserBot moved fast in 2025–26. Moat = in-place patch + local/offline OSS + learning-first framing, NOT "generates a diagram" (commoditized).
11. **Structured-output limits** — schema validity ≠ semantic validity. → per-view chunked generation + deterministic orphan/ID validators + targeted regen.
12. **Token-cost economics unmeasured.** → incremental recon diffs, skip-unchanged-views, never pass full manifest to the model.

## Per-dimension findings (with adversarial critique)

> Each brief was rated by an independent fact-checker. Where a critique corrected a claim, the correction is reflected in the synthesis above. "Trust %" is the critique's own verdict.

1. **React Flow fitness** — All required components are in the free MIT core (Pro gates only examples/support). Controlled-state + `toObject()` is a near-perfect fit for update-in-place.
